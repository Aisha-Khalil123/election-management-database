# Election Management Database (SQL Server)

A relational database for managing a presidential election, covering citizens, candidates, televised debates and polling stations. It has role-based access for five types of users. Built for the *Database Design and Development* course at Al Hussein Technical University (Summer 2024).

## Overview

The system lets:

- **Citizens** view candidates, debates, polling stations and results
- **Candidates** view their own information, their debates and the results
- **Station administrators** manage and count the voters registered at their station
- **Administrators** manage the whole election process
- **Technicians** maintain the data

A web front end was generated with a PHP generator tool. See the user and technical documents in `docs/`.

## Database design

| Table | Purpose | Key relationships |
|-------|---------|-------------------|
| `Candidates` | Candidate and vice-president details, email (unique), biography | 1 → many Citizens (votes); many ↔ many Debates |
| `Citizens` | Voter details: SSN, name, date of birth, address, gender (check `M`/`F`, default `M`) | FK → Candidates, FK → Stations |
| `Stations` | Polling stations with opening and closing times | 1 → many Citizens |
| `Debates` | Debate date, time and venue | many ↔ many Candidates |
| `Citizens_PhoneNumber` | Multi-valued phone numbers (composite PK) | FK → Citizens |
| `Candidates_Debates` | Junction table for the many-to-many relationship (composite PK) | FK → Candidates, FK → Debates |

**Constraints used:** primary and composite keys, foreign keys with `ON UPDATE / ON DELETE CASCADE` (and `NO ACTION` where needed to protect votes), `NOT NULL`, `UNIQUE`, `CHECK` and `DEFAULT`.

## Views and stored procedures

| Object | Type | What it does |
|--------|------|--------------|
| `CandidateVoteCount` | View | Number of votes per candidate (election results) |
| `StationVoterCount` | View | Number of voters per polling station |
| `AddCitizen` | Procedure | Registers a new citizen with all their details |
| `getCandidateInfo` | Procedure | Returns a candidate's details and all their debates, searched by first name |

## Security: roles and permissions

| User | Permissions |
|------|-------------|
| Administrator | SELECT, INSERT, UPDATE, DELETE on the whole database (WITH GRANT OPTION), and runs all procedures and views |
| Station Administrator | View and update Citizens and Stations, view `StationVoterCount` |
| Technician | SELECT, INSERT, UPDATE on the database |
| Candidate | View Candidates, debates and results |
| Citizen | View Candidates, Stations and results; run `getCandidateInfo` |

## Testing and validation

`elections_full_script.sql` includes tests showing that the constraints work:

- Duplicate and NULL primary keys are rejected
- Foreign keys that point to a candidate who doesn't exist are rejected
- NOT NULL, UNIQUE (email) and DEFAULT (gender) behave as expected
- Cascade and no-action rules on update and delete
- Output validation with WHERE, INSERT, UPDATE, DELETE and GROUP BY queries

## Files

| File | Description |
|------|-------------|
| `schema.sql` | Clean script, generated by SQL Server Management Studio, that creates the database, tables, constraints, views, procedures and users |
| `elections_full_script.sql` | Development script: creates tables, inserts sample data, runs the constraint tests, and defines views, procedures, logins and permissions |
| `docs/technical_document.pdf` | Technical documentation: physical schema, DFDs, flowcharts, maintenance, validation and suggested improvements |
| `docs/user_document.pdf` | User guide for each role, with screenshots of the PHP interface |

## How to run

1. Open **SQL Server Management Studio** (SQL Server 2019 or later).
2. Run `schema.sql` to create the database objects. Alternatively, run `elections_full_script.sql` step by step to see the data and tests.
3. The logins use placeholder passwords. Change them before any real use.

## Tools
